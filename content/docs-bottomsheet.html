Bottom sheet

A full-width panel that rises from the bottom over a dimmed page. Use it for a deep, wide view of something the user clicked — a full table or a side-by-side analysis — while keeping the page behind it.

Cube Core

Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

At a glance

A bottom sheet docks to the bottom of the screen over a 40% black scrim. It is full width and about 78% tall, so the top of the page stays visible and users keep their context. The header holds the heading, an optional context switcher and the close button; below it the content is one wide area, or Divided into a white left panel and a grey right panel, each with a slot.

Use it for

A deep, wide view of something the user clicked — a full table, a side-by-side analysis — while keeping the page behind it.

Divided or not

Divided (default): main content left, supporting data right. Off: one wide area, e.g. a full table.

Not a bottom sheet

Narrow details: a Right overlay. A short decision: a Modal. Long multi-step work: a new page.

How it’s built

Three components. ① Bottom-sheet is the whole sheet: it always has ② Bottom-sheet-Header on top, and with Divided on, ③ the Divided panel is its right half. Content goes into the slots.

① Bottom-sheet

Header + content area. Divided = true splits the content into a white left panel and a grey right panel (720 each).

② Bottom-sheet-Header

Heading + optional switcher and description, close button (right), optional Primary tabs.

③ Divided panel

Grey (Screen-bg-2) right half of a divided sheet: optional tabs + a slot (Message, Trends-composition, Table-template). Still named “Right Overlay-Divided-Panel”.

Bottom sheet, Right overlay or Modal?

Use a bottom sheet for a deep, wide view of something the user clicked (a full table, a side-by-side analysis) while keeping the page behind it. Use a Right overlay for narrow details, a Modal for a short decision, and a new page for long multi-step work.

Writing content

  • Heading — what the sheet shows. Never leave the default “Heading”: users lose context.
  • Switcher — “for ‹ Label: Value ›”: the item the sheet is about (a SKU, brand or city). Turn it on when users step through items.
  • Description — one line of context, only if needed.
  • Content heading — a heading and a description for the left panel (Show Heading).
  • Tabs — only when a panel has several views.
  • Slots — system components: Table-template, Trends-composition, Communication/Message.

How to add one in Figma

Step-by-step for designers: adding a bottom sheet to a flow.

  1. Place it on the screen
    Duplicate the screen frame, add a 40% black scrim, then Assets → “Bottom-sheet” at the bottom (X 0, Y = frame height − 800).
  2. Set the header
    Heading = what the sheet shows. Switcher on to move between items (“for ‹ SKU ›”). Description only if needed.
  3. Choose Divided
    Divided on: main content left, supporting data right. Off: one wide area (e.g. a full table).
  4. Fill the slots
    Left slot: Table-template, Message or your content. Right panel slot: Trends-composition, Table-template or Message. Tabs on either side for multiple views.
  5. Annotate behaviour
    Slides up (250ms), closes with ×, Esc or clicking the scrim; content scrolls under a fixed header.

Before you hand off

  • Bottom sheet is the right choice (wide content, keep page context).
  • Placed at the bottom over a 40% scrim; page top visible.
  • Heading named; switcher on if users step through items.
  • Divided only when left and right are related.
  • Slots filled with system components (Table-template, Trends, Message).
  • Close / Esc / scrim behaviour annotated.
