File upload

A drop zone where users drag a file or click to browse to import data (inventory, sales, keywords, guardrails, assortment). It shows upload progress and a list of files, each with a status: ready, uploading, uploaded or failed. The Specifications tab lists every value.

Cube Core

Figma
Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

At a glance

Upload is how people bring data in from a file. They drag a file onto the dashed drop zone or click it to browse; each chosen file appears underneath as its own File upload item with a status, and a progress bar shows the upload while it runs.

Use it for

Importing data from a file: inventory, sales, keywords, guardrails, assortment. Most flows: download the template, fill it offline, upload.

Built from

① Upload (the drop zone) → ② _Progressbar while uploading → ③ one File upload item per file.

Ends in

Success, or Error with a clear reason. Enable the primary action (Upload / Apply) only when every file is valid.

    Anatomy

    Three parts: Upload (the drop zone, with an optional progress bar and a file list slot), _Progressbar, and File upload item (one file with its status). Use Upload; the other two are placed for you inside it.

    ① Upload

    Dashed drop zone (icon, title, helper). “Progressbar” shows upload progress; “Slot2” shows the file list slot where File upload items go.

    ② _Progressbar

    8 · 12 · 16 px bar with an optional “Count” (%).

    ③ File upload item

    One file: icon · file name · status line · remove ×. State = Neutral (ready) · Success · Warning (pending) · Error (failed).

    Common layouts

    Upload usually sits in a Popup titled “Upload <thing>”, under the template link and any required fields, at Fill container width. Three patterns from product screens build on it.

    Do’s and don’ts

    Five rules from the Figma usage guidelines. Each pair shows the right and wrong way, and why.

    Content

    Do

    Upload sales.CSV, .XLSX, .XLS · max 50 MB

    Say what to upload and the rules in the helper (formats · size · rows). Users get it right first time.

    Don’t

    Upload InventoryClick or Drag and Drop .CSV here

    Don’t leave the default text. “Upload Inventory · .CSV” on a sales upload is wrong.

    Do

    final_template_210336.CSVWrong format — only .csv is allowed

    Explain why a file failed. Users know how to fix it.

    Don’t

    final_template_210336.CSVUpload failed

    Don’t just say “Upload failed”. Users don’t know what to change.

    File list

    Do

    final_template_210336.CSVUploaded successfully
    final_template_210336.CSVUpload pending
    final_template_210336.CSVUpload failed

    Show each file as its own item with its own status. Clear when several files are uploaded.

    Don’t

    Some files failed to upload

    Don’t summarise multiple files in one message. Users can’t tell which file failed.

    Do

    final_template_210336.CSVReady to upload

    Keep the remove × so users can replace a file. Easy recovery from mistakes.

    Don’t

    final_template_210336.CSVUpload failed

    Don’t hide the remove button on failed files. Users get stuck with a bad file.

    Do

    Show progress while uploading. Users know it’s working.

    Writing content

    • Title — what is uploaded: “Upload sales”, “Upload Inventory”. Rewrite it for every upload; never ship the default on a different flow.
    • Helper — the action plus the rules: formats · size · rows (“.CSV, .XLSX, .XLS · max 50 MB”). Title and Helper are text layers, not properties — edit the layers.
    • File name — the full name with its extension. If it’s long, truncate in the middle so the end and the extension stay visible.
    • Status — “Ready to upload”, “Upload pending”, “Uploaded successfully”. For a failure, say what’s wrong and how to fix it: “Wrong format — only .csv is allowed”, “Too large”, “3 rows have errors” — not just “Upload failed”.
    • Template link — “Download template” or “Download current data”. When users edit existing data, prefill the template with the current values.
    • History — give the exact failure reason: “Missing required columns: …”.

    How to add one in Figma

    Design an upload flow in five steps.

    1. Place Upload
      Usually in a modal titled “Upload <thing>”, under the template link and any required fields. Set width to Fill container.
    2. Write Title and Helper
      Title = what (“Upload sales”). Helper = formats · size · rows.
    3. Show the file list
      Turn Slot2 on. One File upload item per file — State = Neutral, “Ready to upload”. Single-file uploads: one item; a new file replaces it.
    4. Design uploading
      Turn Progressbar on; set the item’s State to Warning, “Upload pending”.
    5. Design the result
      Success: “Uploaded successfully” — enable Upload / Apply. Error: write the reason in the status line; offer retry / “Download errors”.

    When the flow needs more

    • Template link — put “Download template / current data” right above or below the drop zone (Action-Button · Naked).
    • Preview — after the file is read, show the first ~10 rows in a Table-template inside the Slot; flag invalid cells before the user confirms.
    • History — on the page, list past uploads (date · user · file · status) with the exact failure reason.

    Before you hand off

    • Title and helper written for this upload (formats · size · rows).
    • Template download next to the drop zone.
    • Ready, uploading, success and error states designed.
    • Error messages say what’s wrong and how to fix it.
    • Primary action disabled until every file is valid.
    • If users edit existing data: offer “Download current data” and a preview before confirming.

    File chosenValidate format and size first, then add an item: Neutral, “Ready to upload”.
    UploadingProgressbar on; the item is Warning, “Upload pending”. Remove cancels the upload.

    FailedThe item is Error with the reason (“Wrong format”, “Too large”, “3 rows have errors”) plus retry / Download errors.
    Multiple filesOne item per file, each with its own state. Single-file uploads: a new file replaces the item.
