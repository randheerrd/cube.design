Overview

Buttons let a person trigger an action — submit a form, open a dialog, confirm a choice. Cube has three button sets built from the same properties: the Action button (Core, Destructive, Supportive), the Neutral button, and the Accent button. Together they span roughly 2,600 variants, so this tab teaches how to choose — and the Specifications tab is where you explore every one.

Choose a button

Pick in three steps: what kind of action is it (action type), how loud should it be (variant), and how much room do you have (size).

Three separate components in code, each documented in Storybook: Button (Neutral, Accent), SemanticButton (Core, Destructive, Supportive), and IconButton (Icon-only).

When to use

Use a button

Whenever an interaction changes state, submits data, or moves someone forward in a flow. If it goes somewhere instead of doing something, it is usually a link.

Don't use a button

As plain navigation between pages with no side effect, or stacked more than once in Filled at the same level — one Filled button per view keeps the intended action clear.

Core button

The default action type. Its Filled variant is the single principal action on a view.

Filled, Outlined and Naked — falling emphasis, same colour.

Destructive button

Reserved for hard-to-reverse actions — delete, remove, revoke. Pair with a confirmation step and never make it the default focus in a dialog.

Supportive button

A positive, confirming outcome — approve, publish, mark done. Use sparingly so its meaning holds.

Neutral button

For actions that shouldn't carry a colour meaning — toolbars, table rows, secondary controls. It's the only set with a Dashed variant (for "add" placeholders) and a Dark mode that inverts for dark surfaces.

Accent button

Eight colours for categorising — tags, filters, chart legends. Accent runs smaller (Medium, Small, Tiny) and has no Pressed state.

Emphasis

Do

One Filled button per view, paired with a lower-emphasis action.

Don't

Two Filled buttons compete and blur the intended action.

Sizing and density

SizeDefaultComfortableUse

Medium28px32pxForms, cards, most product UI

Tiny (Accent)16pxInline tags and chips

Fit content (Naked only) drops the padding so a text action lines up with surrounding copy.

Modifiers

Icons

  • Leading icon is shown by default; a trailing icon is available but hidden by default.
  • One icon per side, sized to the button (16px on Large).

Icon-only

Square, same height as the button. Always give it an accessible label and a tooltip.

Rounded

Pill shape for filters and chips; keep one shape per group.

States

Default, Hover, Pressed and Disabled — identical rules across every variant. Disabled is muted and unfocusable; explain why with inline copy, not the button.

Content

A label is a verb plus what it acts on — "Save changes", "Delete file". One to three words. Width follows the label so longer translations never wrap.
