Patterns

Empty states

Stable Last updated Oct 2026

An empty state fills an area that has nothing to show. It says what’s missing, why, and what to do next, in four sizes to fit a page, widget, card or table. The Specifications tab lists every value.

Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

API and behavior

Designers place Empty-state in the empty area, pick the Size, swap the illustration and write the heading, description and actions. In code it is rendered in place of the content when there is no data.

<EmptyState
  size="medium"
  illustration="empty-drawer"
  title="No SKUs match these filters"
  description="Try removing a filter or changing the period."
  actions={[{ label: "Clear filters", variant: "outlined", onClick: clearFilters }]}
/>
TopicRuleNotes
WhenNo data, no results, no access or an errorRender it in place of the content, not on top of it.
Filters and search“No results” + Clear filtersKeep the filters visible so people can change them.
LoadingA skeleton, not the empty stateShow the empty state only once loading has finished.

Source

Values come from the Empty states — Documentation frames in the Cube Core Figma file (Anatomy, Property, Color Annotation, Dimensions, API, Usage Guidelines, How to use) and the live Empty-state and Empty-state illustrations components.

Where Figma disagrees with itself or leaves gaps: the docs give the illustration sizes as 192 / 160 / 128 / 96 wide, but Empty-Drawer is drawn about 88% of that inside its frame, and No-data-swimlane is 172 wide inside 192. “Max 2 lines” for the description is guidance only — the component doesn’t cut the text; this site clamps it to two lines. The Large heading uses the Title font family and the others the Body family (both DM Sans). There is no lock illustration for “No access” yet, and five more illustrations are drafts, not components. Figma has no focus state for the buttons; this site shows a 2px Primary/600 ring.
