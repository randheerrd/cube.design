We design the decision.

Not the dashboard, not the chart, not the screen — the decision somebody has to make at eight in the morning with incomplete data.

GobbleCube builds software that tells people what to do about their business. That is a heavier promise than most software makes, and it changes what good design means here.

A product that merely displays data can afford to be beautiful and vague. A product that recommends a price change or predicts next week's demand cannot. Every screen we draw either earns a decision or wastes someone's morning.

/ 01 — Philosophy

beliefs / 6

What we believe(6)

Principles tell you what to do. Philosophy tells you why, so you can work out what to do when no principle covers the case in front of you. Listed in priority order — when two conflict, the lower number wins.

/01

We design decisions, not dashboards

The unit of value is a person changing their mind — not a chart. Name the decision before you draw anything.

Brief /02

Confidence is a design material

Whenever the machine is guessing, the interface says so — and says how hard it is guessing.

Uncertainty /03

Density is respect

Experts want more per screen arranged well, not less arranged prettily. Clutter is undifferentiated; dense is not.

Layout /04

The interface shrinks as trust grows

Day one needs the explanation. Month nine needs the answer and a keyboard shortcut.

Time /05

We design the recovery, not the happy path

A flow is not designed until someone can get out of it. Every error says what to do next.

States /06

Latency is a design problem

We design what the screen looks like at 200ms, at 2s and at 20s. A skeleton that never resolves is a design bug.

Speed

/ The short version

We would rather show less and be trusted than show more and be checked.

/ 02 — Principles

rules / 8

Eight rules with teeth(8)

A principle is only useful if it can lose an argument for you. Each carries its own stated exception — one of the eight has none at all.

/01

Show the work

Every number on screen traces to where it came from, in one interaction.

Bends /02

One decision per screen

A screen answers one question. Everything else on it is context for that question.

Bends /03

Default to the boring pattern

Novelty is a cost paid by every user, forever. It has to buy something.

Bends /04

Make the machine's certainty visible

Predicted, estimated and recorded values never look alike. This one has no exception.

No exception /05

Glance, scan, dig

Three depths, always in that order, on every dense surface.

Bends /06

Never block on the AI

Every automated path has a manual one beside it.

Bends /07

Words are the interface

Copy is design work, written by the designer, not borrowed from the schema.

Bends /08

Four states or it does not ship

Empty, loading, error and too-much-data are part of the design, not edge cases.
