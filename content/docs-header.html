Components

Header

Stable Last updated Oct 2026

The bar at the top of every product page, right of the navbar. Three stacked rows — what page and which period, sub-view tabs and page actions, and filters — switched on per page. The Specifications tab lists every value.

Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

At a glance

The header sits at the top of every product page, to the right of the navbar. Page header v2 stacks three rows. Every page uses the same component; what changes is which rows and info pieces are switched on.

① Main header

Tells people what page they are on and which time period the data covers. Always visible and sticky.

② Navigation & actions

Lets people switch sub-views with tabs and act with page buttons. Optional; scrolls with the page.

③ Filters

Lets people narrow the data with filter chips and the MRP/SP toggle. Optional.

How to add it in Figma

  1. Place it
    In Assets, find Page-header-v2. Put it at X 256 (right of the navbar), Y 0, 1184 wide to fill the rest of the screen. Don’t use the deprecated per-screen templates.
  2. Name the page
    Select the nested Main header and set Module Name (for example “Availability”). Set the platform: Cross Platform or a specific one.
  3. Set the time period
    Pick the period chip (MTD, L7D, L30D…) and dates. Set Compare with — or turn Period comparison off for real-time pages.
  4. Choose the info pieces
    Data till on when data has a lag. Darkstore count on for quick-commerce data pages, off for Performance Marketing. GobbsIQ on where the assistant is available.
  5. Row ② — tabs and buttons
    Turn Page-Navigation & Action on if the page has sub-views or page buttons. Rename the tabs and set Button 1, Button 2 and their labels.
  6. Row ③ — filters
    Turn Filters on if the page can be filtered. Turn MRP/SP Toggle on only for Digital Shelf pages.

Before you hand off

  • Page header v2 is used (not a deprecated template) and not detached.
  • Module Name and platform are set for this page.
  • Time period and compare-with are set, or compare is off for real-time data.
  • Info pieces match the page type (see the quick setup table).
  • Row ② is on only if there are tabs or page buttons, and their labels are renamed.
  • Row ③ is on only if the page can be filtered; MRP/SP only on Digital Shelf.

Writing content

  • Page name — the exact name from the navbar: “Availability”, “Category RCA”. Never leave the default “Watch Tower”.
  • Tabs — one or two words each, in sentence case: “Overview”, “Share of search”. Three to five tabs at most.
  • Page buttons — start with a verb: “Create rule”, “Export”. The Filled button is the one main action.
  • Info strips — a short lead-in and a bold value: “Data till 12 May’24”.
  • Filters — nouns for the dimension: Platform, Brand, City. Applied chips show the value and “+N”.

StickyRow ① stays at the top; rows ② and ③ scroll with the page.
Global stateTime period, compare-with and filters are page state shared by every widget. Changing them refreshes every widget; keep them in the URL.
Compare withHidden on real-time pages such as Supply Chain Action.
NavigationSegmented or Primary tabs, never radios. Use role="tablist" and arrow-key movement between tabs.
