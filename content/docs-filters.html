Filters

Stable Last updated Oct 2026

Filters let people narrow the data on a page. The filter bar in the page header holds one trigger per filter; a trigger opens a menu to pick values or set a rule, and Apply commits the choice. The Specifications tab lists every value.

Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

At a glance

Filters narrow the data on a whole page. They live in the page header and work in steps: the filter bar shows the available filters, the user opens one trigger, picks values or sets a rule in its menu, then presses Apply.

1 · Filter bar

Header/Page-Filters → Filter-panel. Sits in row ③ of Page header v2 with up to 5–6 triggers, “More filters”, “Clear all” and the MRP/SP toggle.

2 · Filter trigger

One button per filter. Empty: the filter name with ⊕. Applied: the value (“Platform | Blinkit +3”) with ✕ to remove it.

3 · Filter menu + Apply

Opens under the trigger. Quick filter = one filter (240 wide). Multiple filters = all filters in one panel (520 wide). Nothing applies until Apply.

Common layouts

Use the filter bar when users need to narrow the whole page’s data. Show the 5–6 most-used filters as Quick filter triggers; put the rest behind “More filters” — or, for pages with many filters (e.g. Performance Marketing), use one “Filters” button that opens the Multiple-filters menu. Use Selection menus for picking values; Conditions menus for rules on numbers or text.

Writing content

  • Filter labels — a noun for the dimension: Platform, Brand, City, Category. Rename every trigger’s Filter label; order them most-used first.
  • Applied value — the first selected value in Filter Value 1 (“Blinkit”), or the rule for Conditions (“> 20%”). Long values cut off at 72px with an ellipsis.
  • +N — how many more values are selected (“Blinkit +3”). Turn >1 values off when only one is selected.
  • Overflow — “More Filters” for the filters that didn’t fit; “Filters” for the single button that opens every filter.
  • Footer — “N selected” on the left of a Quick menu; “Apply filters (N)” in the Multiple-filters menu so people know how many will apply.
  • Conditions — plain verbs: is, is not, greater than, less than, between, contains.

How to add filters in Figma

  1. Start from the page header
    Filters come with Page-header-v2 — turn its “Filters” toggle on. On its own: Assets → “Header/Page-Filters”. Turn the MRP/SP Toggle on only for Digital Shelf pages.
  2. Choose and order the filters
    In Filter-panel turn Filter 2…6 on or off for the number you need (max 5–6). Rename each trigger’s Filter label — most-used first. More than 6 → turn on More filters.
  3. Show applied filters
    On each applied trigger: Filter Applied = Yes, type the first value in Filter Value 1, keep >1 values on if more are selected. Turn Show Clear-filters on.
  4. Show a menu open
    Set the trigger State = Focused / Selected. Place a Filter-menu 4px below it: Quick filter for one filter, Multiple filters for the “Filters” button. Filter type: Selection (values) or Conditions (rules).
  5. Fill the menu
    Rename options, check the selected ones and update the footer count (“3 selected”). Multiple filters: select the active filter on the left and set the Count-chip numbers.
  6. Annotate behaviour
    For developers: changes apply on Apply; Cancel or a click outside discards; ✕ on a trigger removes that filter; filters are kept in the URL.

Before you hand off

  • The filter bar is in the page header (not detached).
  • 5–6 filters at most; the rest under More filters or the Filters button.
  • Every trigger label is renamed; most-used first.
  • Applied triggers show the value + “+N”; Clear all appears only when something is applied.
  • Menus use the Filter-menu component, not hand-drawn ones.
  • Selection vs Conditions is chosen correctly.
  • Apply / Cancel behaviour is annotated.
  • MRP/SP is on Digital Shelf pages only.

Behavior & accessibility

TopicWhat to do
Draft vs appliedChanges in a menu are a draft. They apply only on Apply; Cancel, Escape or a click outside discards the draft.
Applied triggerShows the first value and “+N”. ✕ removes that filter immediately, without opening the menu.
Clear allVisible only when at least one filter is applied. Resets every filter.
OverflowMore than 5–6 filters → “More filters”, or a single “Filters” button with the Multiple-filters menu.
PersistenceFilters are page-level state: keep them in URL params or saved views, so people return to the same filters.
CountsA Count-chip per filter group in the Multiple-filters menu; the total on the “Filters” button.
KeyboardTriggers are <button>s with aria-haspopup and aria-expanded. Focus moves into the menu on open and back to the trigger on close. Escape closes.
OptionsEach option is a checkbox (role="checkbox", aria-checked); Select All is mixed when some are checked. Search filters the list as you type.
AnnounceAnnounce the result count after Apply (“Showing 3 of 7 SKUs”) in a polite live region.
