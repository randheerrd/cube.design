Dashboard widget

Stable Last updated Oct 2026

The card that holds each block of a dashboard: a Widget-header with the name, context and tools, and a slot for one content block. The Specifications tab lists every value.

Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

At a glance

A dashboard widget is the card that holds each block of a dashboard. A Widget-header on top says what it is, for which context, and holds the tools to act on it; a Widget-content slot below holds the data view.

One widget, one question

Put one content block in the slot — a table, a trend, KPI cards or a comparison.

Name and context

Name it after the question it answers and show the at / for context the numbers depend on.

Keep the header lean

Four tools at most, one Filled button. The header must never wrap.

Writing content

  • Widget name — the question the widget answers, in two or three words: “Revenue trend”, “Top SKUs”, “Brand comparison”. Sentence case.
  • Context chips — short values: “MRP”, “SP”, “All Cat.”, “Dairy”. They complete “at …” and “for …”.
  • Buttons — a verb for what happens: “Export”, “Add SKU”.
  • No placeholder text — replace “Widget Header” before hand-off.

How to add one in Figma

  1. Insert the widget
    In Assets, use “Dashboard-widget”. Place it in the page content area (below Page-header-v2), full width (1160), 16px below the previous widget.
  2. Name it
    Select the nested Widget-header and set Widget Name (“Revenue trend”). Swap Widget-icon to match the content.
  3. Set the context
    Turn At / For on when the numbers depend on the price basis or scope, and edit the chips (MRP, All Cat.). Turn Show Watermark on only for AI or GobbleCube-powered widgets.
  4. Pick the tools
    Turn off what you don’t need — Legend, Drop-down, Search, Icon Button and Collapsible are on by default. Add Filled / Outlined buttons, Column select or View-switch only if needed. Four tools at most.
  5. Fill the slot
    Click the Widget-content slot and insert the content: Table-template, Trends-composition, Metric-trends-group, Swimlanes-composition, Tabs, Message or Empty-state.
  6. Check the empty and loading states
    Design the empty state (an Empty-state in the slot) and note the loading skeleton for developers.

Before you hand off

  • Dashboard-widget is used (not the deprecated metric-card widget) and not detached.
  • The Widget Name is changed and the icon matches the content.
  • The at / for chips show the right context, or are off.
  • Only the tools you need are on (four at most); one Filled button at most.
  • One content block in the slot; the empty state is designed.
  • Widgets are full width, 16px apart, ordered summary → trend → detail.

Behavior & accessibility

TopicWhat to do
LoadingA skeleton in the slot. The header stays visible.
Empty or errorAn Empty-state or Message in the slot. Never leave the slot blank.
CollapseOnly the header shows when collapsed. Remember the choice per user. The chevron is a <button> with aria-expanded.
Context chips“at MRP / for All Cat.” update with the page filters.
Tools overflowFour tools at most; move extras into an overflow menu. The header must not wrap.
WidthFill the page content. Stack widgets with a 16px gap.
SemanticsEach widget is a <section> labelled by its name (a heading). Icon-only buttons need an aria-label.
