Filters

Stable Last updated Oct 2026

Filters let people narrow the data on a page. The filter bar in the page header holds one trigger per filter; a trigger opens a menu to pick values or set a rule, and Apply commits the choice. The Specifications tab lists every value.

API and behavior

Designers: the bar comes with Page-header-v2; set which filters show and their applied values on each Filter-trigger; place a Filter-menu under the trigger to show the open state. Developers: filters are page-level state (URL params) — render the bar from a filter config; menus edit a draft that is committed on Apply.

const filters = [
  { key: "platform", label: "Platform", type: "selection", options: platforms },
  { key: "brand",    label: "Brand",    type: "selection", options: brands },
  { key: "budget",   label: "Budget utilization", type: "conditions",
    conditions: ["is", "is not", "greater than", "less than", "between"] },
];

<PageFilters
  filters={filters}
  value={applied}              // { platform: ["Blinkit", "Zepto"], budget: { op: "greater than", value: 80 } }
  onApply={setApplied}         // called once, on Apply — sync to URL params
  maxVisible={6}               // the rest go under "More filters"
  priceToggle="mrp"            // Digital Shelf pages only
/>
TopicRuleNotes
Draft vs appliedChanges apply on ApplyCancel / click outside discards the draft.
Applied triggerFirst value + “+N”✕ removes that filter immediately.
Clear allVisible when ≥1 appliedResets all filters.
Overflow> 5–6 filters → More filtersOr a single “Filters” button with Multiple-filters menu.
PersistenceURL params / saved viewsSame filters when the user returns.
CountsCount-chip per filter groupTotal on the “Filters” button.

Related components

ComponentUse it instead when
DropdownChoosing a value inside a form, not filtering the page.
HeaderYou need the rest of the page header — the filter bar is its row ③.
Date SelectorFiltering by time period — that lives in the header’s main row, not the filter bar.
Segmented-controlsSwitching between two to five views of the same data (like MRP / SP).
Chips, Tags & LegendsShowing a status or category, not an editable filter.
Empty statesFilters return no results — show “No … match these filters” with Clear filters.

Source

Values come from the Filters — Documentation frames on the Filters page of the Cube Core Figma file (Anatomy, Properties, Color Annotation, Dimensions, API, Usage Guidelines, How to use) and the live Header/Page-Filters, Filter-panel, Filter-trigger, Filter-menu, Secondary-navigation, Count-chip, Modal-Footer and MRP/SP Toggle components.

Where Figma disagrees with itself or leaves gaps: the colour table gives “—” for the background and border of a hovered, not-applied trigger, but the component uses Primary-text/50 and Secondary-text/300 — this site follows the component. The API table defaults Show Clear-filters to false while the Filter-panel component ships with it on. Filter-menu had no instances when it was documented — designs were rebuilding menus by hand. The condition list (“greater than”, “between”…) isn’t drawn; it’s styled here like the menu rows. The components’ sample text is “Category” / “Value”; examples here use real values (“Platform | Blinkit +3”). Unselected option text is a mix of Secondary-text/800 and /950 in Figma; this site uses /800. Figma has no keyboard focus ring for triggers; this site shows a 2px Primary/600 ring. Table-column filters are still explorations, not components.
