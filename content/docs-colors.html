How to read a colour name

Every variable name has three parts separated by “/”.

Semantics

Group — what kind of colour (Semantics, Accent, Platform, Brand, Neutrals)

/
Primary

Ramp — the hue / meaning (Primary, Error, Pink, Blinkit…)

/
600

Step — lightness from 50 (lightest) to 950 (darkest)

The 50 → 950 scale

Each ramp has 11 steps. Lower numbers are lighter. Step 600 is the “main” colour of most ramps; the rest are for tints, borders, hover and pressed states.

PrimaryExample ramp
50–100Backgrounds, selected tints
200–300Borders, dividers
400–500Hover borders, icons
600Main colour
700–800Hover / pressed
900–950Darkest text

Modes

The “Colors” collection has two modes: OKLCH (the default — ramps built in OKLCH so each step is perceptually even) and Mode 1 (the older hex ramps, kept for reference). The Error, Warning, Success and accent ramps (Pink, Purple, Green, Orange, Bronze, Light Blue, Blue) differ between the two; neutrals, text, Primary, Brand and platform colours are identical. Designers work in OKLCH, and every hex on this site is the OKLCH value.

Semantic colours

Semantic ramps carry meaning — use them for interface states, text and actions (group Semantics/*). The ringed swatch is each ramp’s main step.

PrimaryBrand actions: CTAs, links, selected states, focus. Main step 600.
SuccessPositive outcomes, growth deltas, “done”. Main 600.
ErrorErrors, destructive actions, negative deltas. Main 600.
WarningCaution, pending, attention. Main 600 (use 900 for text on white).
Primary-textMain text & icons. 950 headings, 500–700 secondary text.
Secondary-textBorders, dividers, muted text, neutral fills. 100–300 borders, 700 body text.
DisabledOnly for disabled UI. 50–200 fills, 400–500 text.

Neutrals

The building blocks for surfaces and overlays: pure white / black with transparency steps, and two screen background greys.

White & Black (alpha)

Neutrals/White/* and Neutrals/Black/* — the number is the opacity (100 = solid, 10 = 10%). Use White/100 for cards and surfaces; Black/40–60 for overlays behind modals; White/70 for translucent elements on colour.

Do’s and don’ts

Do

Semantics/Primary/600

Use a variable for every colour — inspect shows the token name.

Don’t

#0A5BE0 (hard-coded)

Don’t paste hex values; they won’t update when the palette changes.

Do

Revenue −8%

Use Semantics colours for status (Success, Error, Warning).

Don’t

Revenue −8%

Don’t use Accent colours to show status — Accent/Red is not “error”.

Do

Apply

Put white text on Primary/600 or darker (check contrast on other ramps).

Don’t

Apply

Don’t put white text on light steps (≤ 400) — it fails contrast.

Do

Blinkit

Use Platform colours only to represent that platform.

Don’t

⚠ Stock running low

Don’t reuse a platform colour for something else (e.g. Blinkit yellow as a warning).

Do

Don’t
