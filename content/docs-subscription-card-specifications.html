Subscription card

New Last updated Nov 2026

The plan card on pricing and subscription pages. Each card shows one plan — name, price, discount, what’s included and allowances — and one action that reflects the user’s relationship with that plan: add, switch, upgrade, downgrade or active. Place 3–4 side by side to compare plans. The Specifications tab lists every value.

API and behavior

Designers: place one Subscription card per plan, edit the text properties, fill the Content slot with Plan Features / Plan Tokens and swap the nested _Plan Action to the user’s state. Developers: <PlanCard name price originalPrice discount period description trialDays current features={[{text, highlight}]} tokens={[…]} action={state} />. Pick action from the user’s relationship to each plan, using the table below.

<PlanCard
  name="Standard"
  price="₹11,250"
  originalPrice="₹15,000"          // with discount: struck through, read as “was ₹15,000”
  discount="25% Off"
  period="Monthly / Platform"
  description="Go deeper, down to each dark store"
  trialDays={7}                    // “Free for 7 days” banner; omit when the plan has no trial
  current={false}                  // Current plan badge + aria-current
  features={[
    { text: "Everything in Lite, plus", highlight: true },
    { text: "Data at a dark store level" },
    { text: "View your dark store coverage on a map" },
  ]}
  tokens={[{ type: "tokens", value: "3000", label: "GC Tokens per month" }]}
  action="Upgrade"                 // Add to cart | Added to cart | Switch plan | Active |
                                   // Upgrade | Downgrade | Downgrade scheduled
/>

Which action when

User’s relationship to the planActionNotes
Not subscribed, no cartAdd to cart
In cartAdded to cartClick again to remove.
Current planActive“Active since <date>”; badge “Current plan” on.

Source

Values come from the Subscription card — Documentation frames on the subscription card page of the Cube Core Figma file (Anatomy, Property, Color Annotation, Dimensions, API, Usage Guidelines, How to use) and the live Subscription card, _Plan Action, Plan Feature and Plan Token components in Subscription card · components (use these).

Where Figma disagrees with itself or leaves gaps: the colour table gives the Trial = Yes background as “Gradient (raw)”, but the card fill stays White — the gradient is the banner, listed on its own row here. Inner glow, banner label, badge, discount chip, Includes label, icon and message colours aren’t in the colour table; they’re read from the components. The usage frame promises eight do/don’t rules but has seven pairs. The Figma plan comparison labels Pro’s action “Upgrade to Standard” and gives Lite an “Everything in Lite, plus” line; following Figma’s own checklist (“Action labels name the right plan”), this page uses “Upgrade to Pro”, starts Lite without the Highlight line and gives Pro “Everything in Standard, plus”. Don’t 02 in Figma keeps the same feature order and only changes the description; this page reorders the features. The Questions token’s default label is “GC Tokens per month”; “Questions per month” is used here. The local icons are Phosphor glyphs (shown with the Phosphor font); FeatureCheck (duotone) and Gift are exported from Figma.
