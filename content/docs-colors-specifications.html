Color

Stable Last updated Oct 2026

Every colour in the product comes from Figma variables — never from a raw hex. Colours are organised in three layers: primitive ramps, theme tokens and the components that apply them. The Specifications tab lists every value.

Guidelines Specifications

Primitive tokens

Collection “Colors” — 286 variables, Mode 1 (hex) values. Token = Group/Ramp/Step, e.g. Semantics/Primary/600. Every ramp has the steps 50 → 950.

Developer handoff

How Figma variables map to code, and the rules developers should follow so design and code stay in sync.

Naming → code

Primitives become kebab-case CSS custom properties prefixed --color-. Theme aliases drop the prefix and group and reference the primitive.

Figma variableCSS custom propertyLayer
Semantics/Primary/600--color-semantics-primary-600Primitive
Semantics/Primary-text/950--color-semantics-primary-text-950Primitive
Accent/Light Blue/300--color-accent-light-blue-300Primitive
Neutrals/White/70--color-neutrals-white-70Primitive (alpha)
text/text-primary--text-primary: var(--color-semantics-primary-text-950)Theme alias
border/border-error--border-error: var(--color-semantics-error-200)Theme alias

Example

Generated from the variables (Mode 1).

:root {
  /* Primitives — Colors collection */
  --color-semantics-primary-600: #025BE5;
  --color-semantics-primary-700: #024DC6;
  --color-semantics-primary-100: #EAF1FF;
  --color-semantics-primary-text-950: #101214;
  --color-semantics-secondary-text-700: #586473;
  --color-semantics-secondary-text-200: #DBDFE4;
  --color-semantics-error-600: #E42828;
  --color-semantics-success-600: #46A758;
  --color-neutrals-white-100: #FFFFFF;
  --color-neutrals-bg-screen-bg-1: #F3F6FA;

  /* Theme aliases — theme collection */
  --text-primary: var(--color-semantics-primary-text-950);
  --bg-primary:   var(--color-neutrals-white-100);
  --bg-tertiary:  var(--color-neutrals-bg-screen-bg-1);
}

.button--primary { background: var(--color-semantics-primary-600); color: var(--color-neutrals-white-100); }
.button--primary:hover { background: var(--color-semantics-primary-700); }

Rules

RuleWhy
Never hard-code hex / rgbEvery value must come from a token so palette updates flow through.
Use theme aliases where they existtext-*, icon-*, border-*, bg-* describe intent and allow re-theming.
Transparency = Neutrals alpha tokensUse Neutrals/White/70 or Black/50 — don’t add opacity to other colours ad hoc.
Map Figma states to CSS statesHovered → :hover, Pressed → :active, Focused → :focus-visible, Disabled → [disabled].
Read the token in Dev ModeSelect a layer → the colour shows the variable name (e.g. Semantics/Primary/600).
OKLCH modeThe Colors collection has an OKLCH mode — export it if you want oklch() values; they match Mode 1 visually.

Known issues to sync (design ↔ dev)

Found while documenting — fix these in Figma so exports are clean.

IssueSuggested fix
⚠ Brand/600 (#034CED) vs Primary/600 (#025BE5) — two main bluesPick one source of truth; alias the other.
⚠ Accent/Green ≈ Semantics/SuccessKeep Success for status only; consider shifting the Accent/Green hue.
⚠ theme border-light-solid & bg-light-solid → Black/100Point to Neutrals/White/100 (as the name suggests) or rename.
⚠ theme bg-steel-blue → Brand/50Point to Accent/Steel Blue/50.
⚠ theme bg-secondary is a colour + 80% opacity objectReplace with a clean alias (e.g. Neutrals/Bg/Screen-bg-2).
⚠ theme border-tertiary = border-secondaryDifferentiate or remove.
⚠ Some components use raw hex (Trendline tooltip #1C1E1F, Checkbox dash #FFFFFF)Bind to tokens (Primary-text/950, Neutrals/White/100).
⚠ Palette page labels “Yellow” and “Secondary”Rename to Warning and Secondary-text to match variable names.

Source

Taken from the Color System documentation in the Copy-of-GC-Design Figma file (7 frames: Overview, Semantic, Accent / Brand / Platform, Neutrals, Theme tokens, Which colour do I use?, Developer handoff). Every hex matches its Figma variable (Mode 1). Notes:

  • Corrected copy. Figma’s Warning note says “use 800+ for text on white”, but Warning/800 is only 3.10 : 1 — these pages say 900 (5.6 : 1). The status-badge recipe title said “text 600/700” while its samples use 700 / 800; it now reads 700/800. The Primary-text range “700–500” is written 500–700. The “white text on 600 or darker” do now notes that Success/600 (3.03 : 1) and Warning/600 (1.78 : 1) fail.
  • Two greys for the same job. Theme tokens use the Primary-text ramp (body text #465058, borders #CAD2D7 / #E3E7EA) while the “Which colour do I use?” lookup — what components actually use — uses Secondary-text (body #586473, borders #DBDFE4 / #E8EAEE).
  • Selected / brand tints differ: theme bg-brand / border-brand use Brand/50 and Brand/200; components use Primary/100 and Primary/400.
  • Failing contrast without ⚠: text-success (3.03 : 1), text-quaternary (3.46 : 1), text-placeholder (1.53 : 1) and icon-warning (1.78 : 1).
  • bg-steel-blue swatch renders #EDF8FF in Figma while its hex column says #F4F7FF (Brand/50).
  • “Teal” is described on two ramps — Bronze (“Teal-green”) and Light Blue (“Teal accent maps here”). Accent Purple / Orange / Pink sit close to Zepto, Instamart / Amazon and Nykaa / FK Mins.
  • Main steps: only 4 of 7 semantic ramps use 600 as their main step, and no main step is marked for Accent or Platform ramps (Blinkit’s recognisable yellow is 500).
  • The Figma frames all carry the title “Color System” and mix “Color” / “colour”; this page keeps the nav’s “Color” title.
