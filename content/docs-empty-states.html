Patterns

Empty states

An empty state fills an area that has nothing to show. It says what’s missing, why, and what to do next, in four sizes to fit a page, widget, card or table. The Specifications tab lists every value.

At a glance

An empty state fills an area that has nothing to show — no data yet, no results, no access or data that isn’t available. It replaces the content, never the header or filters, and always says why it’s empty and what to do next.

Show it when

A list, table, chart or page has no content after loading has finished.

Pick the size

Large for a page, Medium for a widget, Small for a card, Tiny for a table or menu.

Not an empty state

Still loading? Use a skeleton. A system problem? Use a Message or a Banner.

Writing content

  • Heading — say what’s missing, specifically: “No SKUs match these filters”, not “No data”.
  • Description — why it’s empty and what to do, in one or two lines: “Try removing a filter or changing the period.”
  • Buttons — a verb for what happens: “Clear filters”, “Create rule”, “Request access”. The default plus icon suits create actions; swap or hide it for the others.
  • Tone — calm and factual. Don’t blame the user and don’t apologise for normal situations.
  • No placeholder text — replace “Empty state heading text.” and the long description before hand-off.

How to add one in Figma

  1. Decide what kind of empty it is
    No data yet, no results, data not available, no access or an error. It sets the illustration, the text and the actions — see Which one do I use?
  2. Insert it in the empty area
    In Assets, use “Empty-state”. Put it where the content would be — the widget slot, card body or table body. Keep the header, filters and search visible.
  3. Pick the Size
    Large: a whole page. Medium: a widget. Small: a card, panel or modal. Tiny: a small card, table body or menu. If the container is narrower than 620, set the width to Fill.
  4. Swap the illustration
    Use the Image property for the current Size (Image-small for Small, and so on) and pick the illustration that matches the situation.
  5. Write the heading and description
    Main Text: what’s missing, specifically. Description: why, and what to do, in two lines at most. Turn Show Description off if the heading says it all.
  6. Set the actions
    Filled for the main next step, Outlined for a secondary one, Ghost for a tertiary one. Rename the buttons. Turn Show Actions off when the user can’t do anything.

Before you hand off

  • The Empty-state component is used, not a hand-drawn version.
  • The Size matches the container and the width fits.
  • The illustration matches the situation.
  • The heading is specific; the description says why and what to do; no placeholder text is left.
  • Actions appear only if the user can act; one Filled button at most.
  • The header, filters and search are still visible.
  • The loading state (a skeleton) is designed separately.

Behavior & accessibility

TopicWhat to do
WhenNo data, no results, no access or an error. Show it instead of the content, not on top of it.
Filters and search“No results” plus a Clear filters action. Keep the filters visible so people can change them.
LoadingShow a skeleton, not the empty state. Show the empty state only once loading has finished.
SizeMatch the container: Large for a page, Medium for a widget, Small for a card, Tiny for a table or menu.
SemanticsThe heading is real text (a heading element when it titles the region). Announce a new “no results” state with role="status".
IllustrationDecorative: alt="". The heading carries the meaning.
ButtonsNative <button>s, in the normal tab order. One Filled button at most.
