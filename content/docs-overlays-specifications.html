Right Overlay

A panel that slides in from the right to show quick, contextual information — drill-downs, details, trends — without leaving the page. The header shows the path of what the user opened, the body is a slot, and an optional footer holds the actions.

API and behavior

Designers: place Right overlay at the right edge over a scrim, set the header (path levels, switchable, tag, tabs), fill the body slot and turn the footer on only if there is an action. Developers: <RightOverlay path={[l1,l2,l3]} switchable onPrev onNext onSelect tag tabs onClose footer={…}>{body}</RightOverlay>.

<RightOverlay
  path={["Whole Wheat", "Organic", "Ahmedabad"]}  // Level 1 › 2 › 3; last = current
  switchable                          // Yes: the last level is a dropdown + ‹ ›
  onPrev={prev} onNext={next}         // step to the previous / next item without closing
  onSelect={select}                   // pick another item at the same level (dropdown)
  tag="MRP"                           // “at MRP” context chip (Show Tag)
  tabs={["Trends", "Competition", "Cross Platform"]}  // views of the same item
  onClose={close}                     // ×, Esc or a click on the scrim
  footer={…}                          // Modal-Footer — only when there is an action
>
  {body}                              // Table-template, Trends-composition, Message…
</RightOverlay>

<!-- rendered -->
<div class="scrim"></div>                           <!-- black 35–40% -->
<aside role="dialog" aria-labelledby="ro-current">   <!-- focus trapped inside; Esc closes -->
  <header>                                          <!-- fixed -->
    Whole Wheat » Organic » <span id="ro-current">Ahmedabad</span> ▾
    <button aria-label="Previous city">‹</button>
    <button aria-label="Next city">›</button> at MRP
    <button aria-label="Close">×</button>
    <div role="tablist">Trends · Competition · Cross Platform</div>
  </header>
  <div class="body">…</div>                         <!-- scrolls -->
  <footer>…</footer>                                <!-- fixed -->
</aside>

Source

Values come from the Right Overlay — Documentation frames on the “Right Overlays” page of the Cube Core Figma file (Anatomy, Property, Color Annotation, Dimensions, API, Usage Guidelines, How to use) and the live Right overlay, Right-overlay-header/Header-with-path, Right-overlay-header/Normal-header and Modal-Footer components.

Where Figma disagrees with itself or leaves gaps: the header masters are 968 wide while the overlay is 760, so every instance is resized (flagged in Figma). Normal-header’s property is “Show tabs” (lower case) where Header-with-path has “Show Tabs”, and its Heading is a text layer rather than a text property (both flagged). The scrim is not part of the component: the Color Annotation recommends Black @ 40%, How to use and the behaviour rules say 35–40%; this site uses 40%. The Dimensions table gives “Prev / next · close: 28 round”, but only the close button is round (pill) — ‹ › have a 6px radius. The Color Annotation gives the current level as SemiBold 13: that is the switcher chip (Switchable = Yes) and its 13px is a raw size, not a text style; on a read-only path the current level is SemiBold 14 (Body/B2/Semibold). The panel’s 16px radius on the left corners is in the component but not in the Dimensions table. Show Tag is documented for the whole header, but the read-only variants (Switchable = No) have no tag, and in the component set the property is only wired on Switchable = Yes · Level 1 — Levels 2 and 3 always show the tag. The SKU-details/MRP chip is bound to Accent/Bronze/200 and /700 but renders #CCEFEB / #0C7F72, not the Bronze values on the Color page (#96F7E4 / #00786F). The footer placed in Right overlay shows Primary only (Cancel, Secondary and the free slot are hidden), while the Anatomy lists the full set; Modal-Footer has no API table. In the Usage frame, Do 03 and Don’t 03 use the same picture — the difference (keeping vs resetting the tab) is behaviour.
