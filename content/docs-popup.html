Components

Popup

Stable Last updated Oct 2026

A dialog that appears over a dimmed page and needs the user’s attention before they continue. A Task modal asks the user to do or decide something; a Message modal reports a state or result. The Specifications tab lists every value.

Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

At a glance

A popup is a dialog that appears over a dimmed page and needs the user’s attention before they continue. There are two kinds, chosen by who acts next.

Task modal

The user does or decides something — confirm a delete, fill a short form, configure one thing. Header, content slot and footer actions.

Message modal

The system reports a state or result — success, failure, maintenance, welcome. Illustration, title and one action.

Not a modal

Browsing details? Use a Right overlay. Quick feedback? A Toast. A long flow? A page.

How to build one in Figma

Task modal

  1. Start from a template if one fits
    In Assets, use “Task-popup-common-templates” for a delete confirmation or a warning. Otherwise use “Task-popup” and build the content yourself.
  2. Set up the header
    Write the title as a short question (“Delete 3 views?”). Turn Header Icon on and choose the intent. Turn for - chip on when the action applies to a specific item.
  3. Fill the content slot
    Click the Modal-Content slot and insert text, fields, a message strip or a list. Keep it short — five fields at most, no scrolling if possible.
  4. Set the footer
    One primary, named with the action’s verb — Destructive for delete. Cancel on; Secondary only for a real alternative. Use the free slot for a “Don’t show again” checkbox.
  5. Place it on the screen
    Centre the modal on the screen frame and add a full-screen scrim behind it (Neutrals/Black/40).

Message modal

  1. Insert and pick a size
    In Assets, use “Message-popup”. Medium for most messages, Large for big moments such as a welcome or a launch.
  2. Choose the illustration
    Swap “Illustration” (Large) or “Illustration (Small)” (Medium) for a graphic from Custom popup graphics that matches the message.
  3. Write the title, message and button
    Title: the result in a few words. Message: one or two sentences. Button: what happens next (“Okay, got it”, “Go to billing”). Add a Secondary button only for a real second option.
  4. Set the gradient
    Turn Linear-gradient-layer on for a softer look and set its colour: Primary (positive or info), Error (failure), Disabled (neutral).

Before you hand off

  • A modal is really needed (not a toast, overlay or page).
  • Task or Message is chosen correctly.
  • The title is short and specific; no placeholder text left.
  • One primary action named with a verb; Destructive for delete.
  • The content fits without scrolling.
  • Centred over a 40% black scrim.
  • The illustration matches the message (Message modal).
  • Close behaviour is annotated: Esc, ×, click outside.

Writing content

  • Title — a short question or statement about the decision or result: “Delete 3 views?”, “Payment successful”.
  • Body — the impact in one or two sentences. Lead with what matters in bold, then the detail.
  • Primary button — the verb of the result: “Yes, Delete”, “Save view”, “Go to billing”. Never “OK” for a destructive action.
  • Cancel — “Cancel”, or a clear alternative such as “Review Metrics”.
  • Illustration — matches the message: Payment, Locked, Card Declined, Under Maintenance and so on.

Behavior & accessibility

TopicWhat to do
Semanticsrole="dialog" and aria-modal="true"; role="alertdialog" for errors. Label it with the title.
OpenTask modal: after a user action. Message modal: on a system event. Fade and scale in over 150–200ms.
CloseTask modal: Cancel, × or Esc; click outside only if nothing would be lost. Message modal: the primary button or Esc — no hidden close.
FocusTrap focus inside. Start on the first field or the primary button, and return focus to the trigger on close.
Enter keyTriggers the primary action — but not for destructive actions.
SizeAt most 80% of the viewport height; the content scrolls while the header and footer stay fixed.
FrequencyShow a message once per event — never repeatedly for the same message.
