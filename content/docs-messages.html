Components

Message

Stable Last updated Oct 2026

A small inline strip that sits next to the content it is about — to inform, warn, confirm success or flag an error for one specific area. Choose the colour by meaning, then Type, Size and Width; the Specifications tab lists every value.

Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

At a glance

A Message is a small strip of text that sits next to the content it is about — above a table, inside a card, under a form field or in a modal — to inform, warn, confirm success or flag an error. Unlike a Banner (top of the page) or a Toast (pop-up after an action), it stays in place while that area is visible.

Three decisions build every message: colour by meaning, then Type (one line, or with a header), then Size and Width.

Is a Message the right component?

Ask these in order and stop at the first “yes”.

2Is it feedback right after an action (saved, exported)?Toast
3Does it explain something on hover?Tooltip
4Must the user decide before continuing?Modal
5Is it about one area — a table, card, field or modal?Message ✓

How to add one in Figma

  1. Insert and place it
    Add Communication/Message from the Cube Core library and place it right next to the content it describes.
  2. Pick the sentiment
    Set Color x Sentiment by meaning: Red for error, Yellow for warning, Green for success, Neutral or White for information, Naked for a quiet hint.
  3. Choose Type, Size and Width
    For example With Header, Medium, Fixed or fill. With Header is Medium only.
  4. Write the text
    Double-click and type a header (two to four words, optional) and one sentence that says what happened and what to do.
  5. Add actions or close if needed
    Turn on Actions (or Actions-bottom), choose which of Button 1 and Button 2 to show, and turn on Removable if people may dismiss it.
  6. Check the icon
    Keep Show Prefix Icon on. Swap the icon inside the set when it fits better — Error → Countdown for expiry, Success → SealCheck for verified.

Before you hand off

  • A Message (not a Banner, Toast or Tooltip) is the right choice.
  • The colour matches the meaning and the icon is kept.
  • It sits right next to the content it describes.
  • It is one clear sentence, plus an optional header, with no placeholder text.

Behavior and accessibility

TopicWhat to do
PlacementNext to the content it describes — above a table, inside a card, under a field.
TruncationTwo lines when the width is fixed. Offer a tooltip or a “Read more” for the rest.
DismissRemovable hides the message. Remember the dismissal if it would otherwise reappear.
ActionsTwo at most, as Naked buttons. Put the main action first as Button 1.
SemanticsUse role="status" for info and success, and role="alert" for errors. Don’t rely on colour — keep the icon and the text.
