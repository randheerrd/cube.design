Banner & Toast

Stable Last updated Oct 2026

Two ways to tell people something happened: a full-width Banner for status that stays, and a dark Toast that confirms an action and disappears on its own. The Specifications tab lists every token.

Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

At a glance

Two ways to tell people something happened. A Banner is a full-width strip at the top of the page for page- or account-level status that stays. A Toast is a small dark pop-up that confirms an action the person just took and disappears on its own.

Writing content

  • Banner message — one sentence. Bold the key value: an amount, a date, a name.
  • Banner actions — Error and Warning only, and only when the person can fix it right away: “Pay now”, “View invoice”.
  • Toast title — what happened, in 2–5 words: “Report exported”, not “Success”.
  • Toast description — optional, max 2 lines. Delete the layer when the title says it all.
  • Toast action — optional, one verb: “View”, “Undo”, “Retry”.
  • No placeholders — never hand off “Main heading” or “Button”.

Accessibility

TopicWhat to do
Banner semanticsrole="status" for information; role="alert" for errors.
Toast semanticsrole="status" with aria-live="polite"; errors use "assertive".
FocusNever move focus to a toast. Its action and close button are reachable by Tab while it’s on screen.
TimingPause the timer on hover and on focus, so people who need longer can read it.
ColourType colour is never the only signal — the icon and the words carry the meaning too.
CloseIcon-only close buttons need an accessible name: “Dismiss” / “Close notification”.

Every exact value — dimensions, colour tokens per type and the full property list — is on the Specifications tab.

Adding one to a screen

Banner

  1. Place it at the very top. Search Assets for “Banner”. Put it at X 0, Y 0 of the screen frame, full width (1440). Move the navbar and page down by the banner height (32 / 36) — don’t overlap.
  2. Pick the Type. Error, Warning, Success, Brand, Neutral or Welcome. Swap the icon only if a suggested icon fits better.
  3. Write the message. One sentence; bold the key value. Error / Warning: add the action button + link if the person can fix it right away.
  4. Decide if it can be closed. Show close = false for issues that must be fixed (overdue payment, suspension). Otherwise keep the ×.

Toast

  1. Place it top-right. Search Assets for “Toast”. Place it just below the page header, 24px from the right edge. Several toasts stack downward 8px apart, max 3.
  2. Pick the Type. Success, Warning, Progress or Error — matching the result. Progress is for background tasks; swap it to Success / Error in the next frame of the flow.
  3. Write title, description and action. Title: what happened. Description: optional, max 2 lines. Action: optional, one verb. Delete the layers you don’t need.
  4. Annotate timing. Note for developers: auto-dismiss (success ~4s, warning ~6s, error 8s+ or until closed), pause on hover.

Before you hand off

  • Banner or Toast chosen correctly — status that stays vs. feedback on an action.
  • Type matches the sentiment.
  • Banner: full width at the top, layout pushed down, one at a time.
  • Banner: Show close decided.
  • Toast: top-right, max 3, title says what happened.
  • Toast: timing and actions annotated for developers.
  • No placeholder text left (“Main heading”, “Button”).
