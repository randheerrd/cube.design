Right Overlay

A panel that slides in from the right to show quick, contextual information — drill-downs, details, trends — without leaving the page. The header shows the path of what the user opened, the body is a slot, and an optional footer holds the actions.

Cube Core

Figma
Guidelines Specifications Code (not in Storybook yet) Accessibility (coming soon)

At a glance

A Right overlay is a 760px panel docked to the right edge, full height, over a dimmed page. Use it to show the details of something the user clicked — a row, a bar, a city — while keeping the page visible. Three parts: a header (the path of what the user opened, close and tabs), a body slot for any content, and an optional footer with actions.

Use it for

Quick, contextual information — drill-downs, details, trends — about something the user clicked, without leaving the page.

Which header

Header-with-path (default) when the item comes from a drill-down; make it Switchable when users compare items one after another. Normal-header for generic panels.

Not a right overlay

Wide content: a Bottom sheet. A short decision: a Modal.

How it’s built

Four components. ① Right overlay is the panel. It always has ② a Right-overlay-header on top — Header-with-path or Normal-header — and ③ the Right-overlay-body slot below. With Show Modal-Footer on, ④ the shared Modal-Footer closes it off.

① Right overlay

760 × full height, docked right. White, 1px Secondary-text/100 border, Elevation/Right-overlay shadow. One property: Show Modal-Footer.

② Right-overlay-header

Header-with-path (default): the path Level 1 › 2 › 3, Switchable, Show Tag, Show Tabs. Normal-header: a heading, close and Show tabs.

③ Right-overlay-body

SLOT — padding 20, gap 16, scrolls. Preferred: Segmented-control, Message, Table-template, Trends-composition.

④ Modal-Footer

A free slot on the left (checkbox / message) and the actions on the right: Cancel · Secondary · Primary.

Right overlay, Bottom sheet or Modal?

Use the Right overlay to show details of something the user clicked while keeping the page visible. For wide content use a Bottom sheet; for a short decision use a Modal.

Writing content

  • Path (Level 1 · 2 · 3) — the item the user drilled into: its parents first, the current item last (e.g. Whole Wheat › Organic › Ahmedabad: category → brand → city). Show the full path, not only the last level.
  • Heading — Normal-header only: what the panel is about. Don’t fake a path with one generic level.
  • Tag — “at MRP”: the price / channel context. Turn Show Tag on when price context matters.
  • Tabs — views of the same item (Trends · Competition · Cross Platform). Keep the selected tab when users switch items.
  • Body — system components: Table-template, Trends-composition, Message, Segmented-control.
  • Footer — only when there is an action: Cancel · Secondary · Primary. The free slot takes a checkbox or a message.

How to add one in Figma

Step-by-step for designers: add a Right overlay in 5 steps.

  1. Place it
    Duplicate the screen, add a 35–40% black scrim, then Assets → “Right overlay” docked to the right edge, full height.
  2. Pick the header
    Drill-down item → Header-with-path (default). Generic panel → swap to Normal-header.
  3. Fill the path
    Level = how deep (1–3); type Level 1 / 2 / 3. Switchable = Yes if users will step through items; Show Tag for price context.
  4. Fill the body
    Put a Table-template, Trends-composition, Message or Segmented-control in the body slot. Tabs switch views of the same item.
  5. Footer only if needed
    Show Modal-Footer for actions (Cancel · Secondary · Primary); turn it off for read-only details.

Before you hand off

  • Right overlay is the right choice (detail of something clicked; page stays visible).
  • Header: path for drill-downs, Normal-header otherwise.
  • Switchable only if users step through items; tab kept when switching.
  • Body uses system components (Table-template, Trends, Message…).
  • Footer only when there is an action; close / Esc / scrim behaviour annotated.
